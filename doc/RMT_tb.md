# 1. tb_rmt_wrapper.v
**测试模块**: `rmt_wrapper`  
**功能**: 综合验证RMT（可重构匹配表）包装器的完整数据处理流水线

### 测试场景划分

#### 阶段1: 基础数据包测试 (报文1-22)
- **报文1-4**: 基本UDP数据包，固定模式
- **报文5-8**: 变化的数据包，测试处理多样性  
- **报文9-12**: 不同序列号的数据包
- **报文13-16**: 扩展功能测试
- **报文17-22**: 复杂数据结构测试

#### 阶段2: 多阶段处理测试
- **Stage 0**: 基础处理阶段测试
- **Stage 1**: 中级处理阶段测试  
- **Stage 3**: 高级处理阶段测试

#### 阶段3: 自定义ASK包测试
- 专门设计的聚合数据包测试
- 验证特殊处理逻辑

## 数据包结构

### 典型数据包格式

**以太网+IP+UDP基础结构**:
```verilog
数据包特征:
- 源MAC: 000a35069eae
- 目的MAC: 08c0eb425e62  
- VLAN标签: 8100000f
- IPv4协议: 0800
- 源IP: c0a86401 (192.168.100.1)
- 目的IP: c0a86403 (192.168.100.3)
- UDP协议: 11
- 源端口: f1f2 (控制端口)
```

### 数据包分片机制

**标准分片模式**:
- **Chunk 1/2**: 64字节完整数据块
- **Chunk 2/2**: 2-26字节尾部数据
- **TKEEP控制**: 精确字节有效掩码

**复杂分片模式**:
- **Chunk 1/3, 2/3, 3/3**: 多分片大数据包
- **可变长度**: 支持不同包大小
- **灵活控制**: 适应各种网络场景

# 5. tb_cookie.v
**测试模块**: `cookie`  
**功能**: 验证基于时间戳的Cookie生成模块的功能和时序特性

### 测试场景：时间戳序列输入
测试模块通过输入一系列96位时间戳值，验证Cookie生成器的响应行为。

### 时间戳输入序列
```verilog
时间戳序列（8个连续变化的值）:
1. 96'hfff12423131243214f234f
2. 96'hfff12423131243214f234e  // 最低位减1
3. 96'hfff12423131243214f2332  // 变化较大
4. 96'hfff12423131243214f2312  // 继续变化
5. 96'hfff12423131243214f2332  // 重复第3个值
6. 96'hfff12423131243214f2312  // 重复第4个值
7. 96'hfff12423131243214f2343  // 新值
8. 96'hfff12423121243214f234e  // 高位部分发生变化
```

- **连续变化**: 前4个时间戳逐步变化
- **重复测试**: 第5-6个重复之前的输入，验证确定性
- **边界测试**: 最后两个测试高位变化的影响

### 核心功能测试
1. **时间戳处理能力**
   - 96位宽时间戳输入的正确处理
   - 时间戳变化的实时响应
   - 高位和低位变化的分别处理

2. **Cookie生成算法**
   - 基于时间戳的Cookie值计算
   - 输出值的稳定性和一致性
   - 32位Cookie输出的有效性

3. **时序特性**
   - 输入到输出的传播延迟
   - 时钟同步性能
   - 复位后的初始化行为

### 特殊测试场景
1. **重复输入测试**
   - 相同时间戳是否产生相同Cookie
   - 验证算法的确定性

2. **增量变化测试**
   - 微小时间戳变化对Cookie的影响
   - 验证算法的敏感性

3. **大幅变化测试**
   - 高位时间戳变化的影响
   - 验证算法的分布特性

# 10. tb_pkt_gen.v
**测试模块**: `rmt_wrapper` + 自定义数据包生成器  
**功能**: 验证数据包生成和RMT处理系统的端到端性能

## 测试参数

| 参数 | 值 | 说明 |
|------|----|------|
| C_S_AXIS_DATA_WIDTH | 512 | AXI-Stream数据宽度 |
| C_S_AXIS_TUSER_WIDTH | 128 | AXI-Stream用户信号宽度 |
| CYCLE | 4 | 时钟周期（2.5GHz） |

## 测试用例

### 数据包生成状态机

**状态定义**:
```verilog
PKT_0(0): 发送数据包第一个字
PKT_1(1): 发送数据包后续字
```

### 数据包结构

**第一个字 (PKT_0状态)**:
```verilog
tdata: 512'h000000000000000002000000040000001a008d201a0013001300090000006f6f6f6fd79b1140000001002e000045000801000081a401bdfefd3c050000000000
tkeep: 全1 (64'hffffffffffffffff)
tlast: 0
```

**后续字 (PKT_1状态)**:
```verilog
tdata: c_counter + counter (动态计算值)
tkeep: 全1
tlast: 根据pkt_len决定
```
